# Profile maintenance

The README is an original red/black design inspired by the terminal-window structure of [GitSkins Terminal](https://www.gitskins.com/templates/terminal). No GitSkins assets or template code are copied.

## Preview and publication

Open README.md on `preview/red-black-terminal` to review all assets together. Relative asset paths work on the preview branch and on main. This branch does not replace the public profile until its PR is merged.

The header uses SVG and CSS animation without scripts or external fonts. It settles into a readable static state, and the reveal/cursor effects respect reduced motion. The typing clip runs once; all text is also described in the image's accessible description.

## Data and privacy

`node scripts/public-stats.mjs` refreshes the stats SVG using unauthenticated GitHub REST requests. It fetches only public owned repositories, sums their stars, and reads the public follower count. It does not read private repositories, commit histories, secrets, or authenticated account totals. Counts are dated snapshots, not real-time counters. API failures stop the update instead of publishing invented zeroes.

The contribution snake is generated by [Platane/snk](https://github.com/Platane/snk) from the GitHub contribution calendar. Its workflow uses only the repository-scoped automatic `GITHUB_TOKEN`, never a personal token. GitHub may include anonymized private contribution counts in a public calendar if the account owner has enabled that setting; the snake contains no repository names or private activity details. It is a visualization, not a claimed commit total.

## Automation

The workflow runs daily at 06:23 UTC on the default branch, on relevant pushes to main or the preview branch, and manually. It commits only the two generated SVGs to the branch it runs on. The preview push initializes the snake before merge; it never pushes to main from the preview branch. All actions are pinned to commit SHAs. No third-party stats card service or personal access token is needed.

If repository rules prevent bot pushes, the refresh job will fail visibly and leave the last successful assets intact. Scheduled workflows only start after the workflow exists on the default branch, and GitHub may disable schedules on inactive public repositories.

Keep biography, skills, and featured projects grounded in information you choose to publish. No role, stack, availability, location, or experience level is inferred from private repositories.
